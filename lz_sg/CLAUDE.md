## 3. 项目核心概念速查表

在开始任何开发工作前，你必须理解以下核心概念：

### 3.1 游戏类型
- **画风**：龙珠风格（肌肉线条、动态姿势）
- **题材**：三国全时期角色混搭
- **玩法**：大富翁探索 + 回合制战斗 + 肉鸽养成

### 3.2 核心机制速查
| 维度 | 关键设计 |
|------|----------|
| 队伍 | 6人阵容共享一套装备、共享一条血条 |
| 蓝条 | 个体独立，普攻回蓝，满蓝自动放大招 |
| 地图 | 大富翁环形转圈，骰子数固定=关卡进度 |
| 战斗 | 骰子数触发强制战斗 + 地图战斗格 |
| 养成 | 关卡内临时强化（buff/技能/装备）+ 永久养成（等级/背包） |
| 稀有度 | 金卡（90保底）、紫卡（10保底）、蓝卡 |
| 阵营 | **无阵营限制**，只有史实羁绊（桃园结义、五虎上将等） |

### 3.3 难度参数速查
| 难度 | 关卡 | 骰子数 | 格子数 | 强制战斗间隔 |
|------|------|--------|--------|--------------|
| 难度1 | 1、3、7 | 15个 | 15格 | 每10个骰子 |
| 难度2 | 2、4、6 | 25个 | 25格 | 每8个骰子 |
| 难度3 | 5、9 | 35个 | 35格 | 每7个骰子 |
| 难度4 | 10 | 50个 | 50格 | 每5个骰子 |
| 福利关 | 8 | 10个 | 10格 | 无战斗 |

### 3.4 属性系统速查
- **基础5个**：生命值、攻击力、防御力、速度、普攻回蓝
- **进阶9个**：暴击率/伤害、命中/闪避、穿透、抗暴、技能伤害加成、最终伤害加成/减免
- **法物共通**：法伤和物伤共用同一套攻击力/防御力模板

### 3.5 阵营定位：软引导 + 自由搭配

**设计原则**：保留魏蜀吴群作为背景标签，但不做硬性限制

**核心机制**：
- 阵营仅作为角色背景和标签使用
- 羁绊系统完全基于史实关系（血缘、君臣、战友、对立、情缘）
- 玩家可自由跨阵营搭配阵容
- 每个角色都有独特的技能机制，不依赖阵营

**羁绊分级触发**：
- 2人羁绊：必须集齐
- 3人羁绊：2人/3人两档效果
- 4人羁绊：3人/4人两档效果
- 5人羁绊：3人/4人/5人三档效果

**角色标签系统**：
每个角色拥有多个标签：#阵营标签 #机制标签 #羁绊标签，便于搜索和搭配

## 4. 开发规范

### 4.1 代码规范
- 所有代码注释使用中文
- 函数/变量命名使用英文（驼峰或下划线根据语言惯例）
- 遵循对应语言的最佳实践（小程序开发）

### 4.2 设计决策流程
1. **先读文档** → 理解现有设计
2. **讨论确认** → 与用户确认修改方向
3. **更新文档** → 同步到 `docs/game-design/*.md`
4. **再写代码** → 基于确认后的设计实现

### 4.3 游戏设计哲学（不可违反）
- **双路径制**：运气好（神级掉落）OR 实力强（阵容碾压），两者都必须能通关
- **极端肉鸽**：不追求完美平衡，接受极端情况出现
- **探索即奖励**：用骰子越多=探索越深=星级越高
