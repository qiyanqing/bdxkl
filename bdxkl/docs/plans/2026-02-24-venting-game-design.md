# 发泄情绪游戏设计文档

**日期：** 2026-02-24
**平台：** 微信小程序
**类型：** 情绪发泄 / 休闲游戏

---

## 一、产品概述

### 1.1 产品定位
一款微信小程序端的情绪发泄游戏，用户可以创建自定义虚拟形象（上传真实照片或选择预制卡通角色），通过多种攻击方式进行发泄，伴随统计系统和社交分享功能。

### 1.2 核心体验流程
1. 用户选择性别 → 上传照片/选默认形象 → 输入名称 → 创建完成
2. 选择攻击技能（物理/魔法/言语/道具） → 点击攻击 → 形象受击反馈
3. 积累攻击次数 → 达成里程碑 → 生成分享海报

### 1.3 技术栈
- **前端：** 微信小程序原生 + Canvas + Spine运行库
- **动画：** Spine 2D骨骼动画
- **AI图像处理：** 腾讯云/阿里云人像抠图API
- **后端：** 云开发（云函数+云存储+云数据库）

## 二、虚拟形象系统

### 2.1 模型方案
选择 **Spine 2D骨骼动画** 而非Live2D：
- 性能更好，小程序环境运行更流畅
- 有现成的小程序运行库
- 发泄游戏不需要复杂面部微表情，主要靠夸张动作

### 2.2 制作流程

#### 预制基础模型（一次性美术工作）
- 男女各一套大头小身骨骼模型
- 头部：预留"照片贴图区域"
- 身体：标准体型，包含动画状态：
  - `Idle` 待机
  - `Hit_Light` 轻度受击
  - `Hit_Medium` 中度受击
  - `Hit_Heavy` 重度受击
  - `Knockdown` 倒地
  - `GetUp` 起身

#### 用户照片处理（动态）
```
用户上传 → 调用抠图API → 提取人像 →
裁剪头部 → 调整比例 → 生成贴图 →
贴到Spine模型头部
```

#### 默认卡通角色
- 预制5-10套Q版头像（男/女各半）
- 用户选择后直接应用，无需AI处理

### 2.3 AI处理技术选型
- **抠图API：** 腾讯云人像分割或阿里云智能抠图
- **成本：** 约0.01-0.05元/次，按量计费
- **处理时间：** 1-2秒
- **备用方案：** 本地Canvas简单裁剪（免费但效果差）

### 2.4 用户与形象关系
```
一个用户 → 多个虚拟形象
每个形象 → 独立的攻击历史和统计
```

**用户操作流程：**
```
打开小程序
  → 首次使用：引导创建形象
  → 老用户：展示"我的形象"列表
    → 选择形象进入攻击场景
    → 点击"创建新形象"按钮
    → 长按形象可删除/编辑
```

## 四、受击反馈系统

### 4.1 反馈维度

| 反馈维度 | 实现方式 | 技术手段 |
|---------|---------|---------|
| 视觉 | 形象晃动、表情变化、打击特效 | Spine动画 + Canvas粒子特效 |
| 听觉 | 打击音效、受击声音 | Web Audio API + 预制音效库 |
| 触觉 | 手机震动 | 微信 `wx.vibrateShort()` API |
| UI | 血条减少、伤害数字飘字 | CSS3动画 |

### 4.2 具体效果

**轻度攻击**（如扇耳手）
- 头部侧偏 + 一次短震动 + "啪"音效 + -10伤害飘字

**中度攻击**（如拳打、魔法球）
- 整体后仰 + 表情痛苦化 + 连续震动 + 爆炸特效 + 伤害飘字

**重度攻击**（如雷电、大型道具）
- 倒地动画 + 屏幕抖动 + 长震动 + 闪电/火焰特效 + 惨叫音效 + 大额伤害飘字

### 4.3 Spine动画状态机
```
Idle → Hit_Light → Idle
Idle → Hit_Medium → Hit_Recover → Idle
Idle → Hit_Heavy → Knockdown → GetUp → Idle
```

### 4.4 微信审核规避
- 不出现血液、断肢等真实暴力元素
- 不使用真实惨叫，用卡通化音效
- 伤害数字用卡通字体，像游戏而非暴力

## 五、分享统计系统

### 5.1 分享触发机制

**被动分享（达到条件弹窗提示）：**
- 特定道具使用达到100次
- 总攻击次数每达到100次

**主动分享（用户随时点击分享按钮）：**
- 统计**本次登录**的所有攻击行为
- 生成综合统计海报

### 5.2 分享海报内容

**被动分享（特定道具达成）：**
```
┌─────────────────────────────┐
│      [角色跪地求饶形象]        │
│                             │
│     100个大嘴巴子，服不服？   │
│                             │
│   [小程序码]  扫码来解压！    │
└─────────────────────────────┘
```

**主动分享（综合统计）：**
```
┌─────────────────────────────┐
│      [角色当前形象]           │
│                             │
│    本次解压报告               │
│    扇耳手 ×58    🔥           │
│    拳打   ×32                 │
│    火球术 ×15    🔥 最高频     │
│    泼水   ×12                 │
│    总攻击 ×117次              │
│                             │
│    你也太狠了！角色已经熟了    │
│                             │
│   [小程序码]  扫码来解压！    │
└─────────────────────────────┘
```

### 5.3 海报生成逻辑
1. 数据统计：本地记录本次登录各道具使用次数
2. 文案选择：根据最高频攻击道具选择对应文案
3. 背景选择：根据总攻击量选择角色状态
4. Canvas绘制：组合角色形象 + 背景图 + 统计数据 + 小程序码

```
│  ┌─────────┐ ┌─────────┐ ┌─────────┐   │
```

### 7.2 数据流

```

```

```
更新本地统计 → 更新UI显示
```

### 8.3 关键页面说明

**首页（我的形象列表）**
- 顶部：标题"我的出气筒"
- 中间：网格展示所有形象卡片
- 底部：固定"创建新形象"按钮
- 卡片内容：头像 + 名称 + 攻击次数 + 长按菜单

**创建形象页**
- 步骤1：选择性别（男/女）
- 步骤2：选择来源（上传照片 / 选卡通）
- 步骤3：预览效果 + 输入名称
- 步骤4：确认创建

**攻击场景页（核心）**
- 上半部：Spine形象动画 + 伤害飘字区域
- 下半部：4类技能按钮组（可左右滑动）
- 顶部：当前形象名称 + 本次攻击统计
- 右上角：分享按钮

### 9.2 核心风险与应对

| 风险 | 应对方案 |
|------|---------|
| 微信审核不通过 | 回避暴力元素、卡通化处理、准备申诉材料 |
| Spine性能问题 | 降低动画帧率、简化骨骼数量、降级到CSS动画 |
| 抠图API成本过高 | 设置每日免费额度、超出后降级到本地处理 |
| 云开发免费额度耗尽 | 按量计费成本低，预估月花费<100元 |

### 9.3 技术备选方案

| 技术点 | 主方案 | 备选方案 |
|--------|--------|----------|
| 动画引擎 | Spine | Lottie / CSS3 |
| 抠图API | 腾讯云 | 阿里云 / 本地Canvas |
| 音效 | Web Audio API | 微信背景音频API |
| 震动 | wx.vibrateShort | 纯视觉反馈 |
